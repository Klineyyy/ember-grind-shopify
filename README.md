# Ember & Grind — Shopify theme + Restock Radar app

A take-home build in two parts that tell one story:

| Part | What it is | Lives in |
|---|---|---|
| **Ember & Grind theme** | Storefront for a fictional specialty coffee roaster, with a *Brew Profile* quiz that matches shoppers to coffees and sells a discounted 3-bag sampler. | [`theme/`](theme) |
| **Restock Radar app** | Embedded Shopify Admin app that scores every variant's stockout risk, recommends what to reorder and by when, and runs the restock (purchase-order) workflow with a full activity log. | [`app/`](app) |

The theme helps customers find the right coffee; the app makes sure that coffee is in stock.
Product and architecture reasoning is in **[APP_DECISIONS.md](APP_DECISIONS.md)**.

## Prerequisites

- **Node.js 20+** (developed on Node 24) and npm
- **Docker** (for MySQL), or any MySQL 8 server
- **Shopify CLI** 3.x or newer — `npm install -g @shopify/cli@latest`
- A **Shopify Partner account** and a **development store** (create one in the Partner/Dev Dashboard → *Stores → Create development store*; leave “test data” unchecked)

## Part 2 first: run the app (it can also seed the store)

The app includes dev-only tools that create the demo catalog in your store, so setting it up first gives the theme real data to show.

### 1. Start MySQL and run migrations

```bash
docker compose up -d mysql            # MySQL on localhost:3306, db "restock_radar", user radar/radar

cd app/web
npm install
cp .env.example .env                  # DATABASE_URL=mysql://radar:radar@127.0.0.1:3306/restock_radar
npm run db:migrate                    # applies the SQL migrations in drizzle/
```

### 2. Create your own copy of the app in Shopify

`shopify.app.toml` contains the original author's `client_id`. Link it to an app in **your** Partner organization:

```bash
cd app
shopify app config link               # choose your org → "create a new app" → name it Restock Radar
```

If the CLI rewrites `shopify.app.toml`, make sure it still contains the scopes and `[[webhooks.subscriptions]]` blocks from this repo.

> **Protected customer data.** The `orders/create` webhook needs a one-time declaration:
> Partner dashboard (partners.shopify.com) → *Apps → Restock Radar → API access requests → Protected customer data access → Request access*.
> Tick **Protected customer data** only (no name/email/phone/address fields), give a reason (e.g. inventory management) and save. A saved draft is enough for development stores.
> Prefer not to? Remove `orders/create` from `shopify.app.toml` — sync still imports order history, you just lose live per-order rescoring.

### 3. Run it

```bash
cd app
shopify app dev                       # pick your dev store, allow URL updates
```

Press **`p`** to open the app, approve the permissions, and it loads inside the Shopify admin.
The CLI injects `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SCOPES`, `HOST` and `PORT`; you don't set them yourself.

### 4. Load demo data (Settings page → *Demo data*, development only)

1. **Seed demo store** — creates metafield definitions, 10 coffees (6 size/grind variants each) and 5 brewing-gear products with stock and branded packshot images, the *Coffee* and *Brewing Gear* collections, the `SAMPLER15` discount (15% off 3+ items) and the main menu. Then syncs everything into the app. Safe to re-run.
2. **Add demo suppliers** — three suppliers with different lead times, assigned to products.
3. **Generate demo sales** — 60 days of simulated order history so the risk engine has something to score. Rows are flagged `is_simulated` and never overwrite real orders.

The dashboard will then show a realistic mix of critical, high, watch, healthy and overstocked products.

### Useful app scripts (`app/web`)

| Command | What it does |
|---|---|
| `npm run dev` | Server + Vite in one process (run by `shopify app dev`) |
| `npm test` | Vitest — risk engine and clearance suggestion unit tests |
| `npm run typecheck` | `tsc --noEmit` over server and client |
| `npm run build` / `npm start` | Production frontend build / start in production mode |
| `npm run db:generate` | Generate a new migration after editing `src/server/db/schema.ts` |
| `npm run db:migrate` | Apply migrations (`0000_init`, `0001_clearance_discounts`) |
| `npm run db:studio` | Drizzle Studio (browse the database) |
| `npm run demo:packshots` | Re-render the demo product images (needs `npx playwright install chromium` once) |

### Trying the main workflow

1. **Dashboard** → *Create restock plans*: one draft purchase order per supplier, pre-filled with recommended quantities.
2. Open a plan → edit quantities → *Save items* → *Mark as ordered* (units now count as incoming; risk drops) → *Mark as received* (optionally adds the units to Shopify inventory).
3. **Activity** shows every step with field-level changes.
4. **Clearance**: open an overstocked product → *Create clearance discount* (or *Clearance → New clearance discount*), accept or adjust the suggested code and % off → *Create in Shopify*. The code works at checkout for those variants only; the Clearance page shows uses, sales and stock cleared.
5. Place a test order on the storefront (Admin → *Settings → Payments* → activate **Test payment gateway**, card number `1`) and watch the product's sales and score update via webhooks.

## Part 1: the theme

### Preview locally

```bash
cd theme
shopify theme dev --store <your-store>.myshopify.com
```

Open `http://127.0.0.1:9292`. Development stores are password-protected; the CLI asks for the **storefront password** (Admin → *Online Store → Preferences → Password protection*).

### Lint

```bash
shopify theme check --path theme
```

### Publish

```bash
shopify theme push --unpublished --store <your-store>.myshopify.com   # first upload: creates a new theme
shopify theme push --theme <theme-id> --store <your-store>.myshopify.com   # later updates to that theme
```

Then *Online Store → Themes → Ember & Grind → Publish*.

### Data the theme expects

Everything works with any products, but the coffee-specific features read these product metafields (namespace `coffee`, created by *Seed demo store*, editable in the product admin):

| Metafield | Type | Used by |
|---|---|---|
| `roast_level` | integer 1–5 | roast meter, quiz roast fit, placeholder colour |
| `origin`, `process`, `altitude` | single-line text | product cards, product page specs |
| `tasting_notes` | list of text | note chips, quiz results |
| `brew_methods` | list of text (`espresso`, `pour-over`, `french-press`, `moka`, `drip`) | quiz method fit |
| `flavor_profile` | JSON `{"sweetness":7,"acidity":8,"body":4,"bitterness":2,"fruit":9}` | flavour radar, quiz flavour fit |
| `decaf` | boolean | quiz caffeine rule |

Other conventions: coffee variants use options **Size** and **Grind** (`Whole Bean`, `Espresso`, `Filter`, `French Press`); gear is tagged `method:<brew-method>` so the quiz can suggest it; the quiz section points at the `coffee` and `brewing-gear` collections and the `SAMPLER15` code (all configurable in the theme editor).

### What's in the theme

- **Pages:** Home, Collection (native storefront filters + sort + pagination), Product, Cart, plus Search, 404, Page, Collections list and a branded Password page.
- **Custom sections:** *Roast hero* (background “roasts” as you scroll), **Brew Profile quiz** (the standout feature), *Origin map* (clickable coffee-belt map), *Flavour profile* (radar chart drawn in Liquid/SVG), *Brew guide* (accessible tabs), *Subscription promo*, *Featured collection*.
- **Cart drawer** rendered with the Section Rendering API, with a free-shipping progress bar and quantity controls.

## Production notes

The app runs as a single Node process: `npm run build` then `npm start` (Express serves the built frontend and the API). Deploying it for real means hosting that process plus a MySQL database (e.g. Render/Fly.io + PlanetScale/RDS), setting `DATABASE_URL`, `SHOPIFY_API_KEY`, `SHOPIFY_API_SECRET`, `SCOPES`, `HOST`, then `shopify app deploy` to push the app configuration. Demo tools are disabled when `NODE_ENV=production`.
